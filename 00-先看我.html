本包是「离线版」吗？ 看根目录有没有 runtime\python314\。
有 → 内部已带 Python 3.14.6 与全部依赖，不需要装 Python、不需要联网，双击 run.bat 即可。
没有（常规版）→ 需要 Python 3.11~3.14，首次启动会 pip 装约 60 MB 依赖（脚本内置清华镜像重试）。

3. 常见问题（先看这四条，能省掉 90% 的麻烦）

  • 双击 run.bat 闪退 → 装 Python 3.11+ 并勾选 “Add python.exe to PATH”，重开窗口；或直接用离线版。
  • 提示「引擎未启动 —— 已有引擎在运行」 → 上次进程没退干净（引擎有单写者租约）。关掉旧窗口/进程后重开。
  • 启动任务报 Key 相关错误 → 没填 .env 里的 DEEPSEEK_API_KEY。不填 Key 只影响“发起新任务”，看演示数据与跑单测不受影响。
  • 端口 8507 被占用 → 关掉占用进程，或改用 --server.port 8508 启动。

4. 我们明确写出来的限制（不是隐瞒）

  • 真跑结果不是逐字节确定：大模型有随机性，可复现的是流程形态与验收结论（节点状态、断言结果、产物结构），不是每句话。
  • 没有向量检索（RAG）：DeepSeek 未提供 embedding 接口；方案书里写清了加它的条件。
  • 沙箱是进程级（子进程 + 独立 venv + 工作区隔离），不是容器级。
  • 画布不是自由拖拽编辑器：它是 YAML 的可视化入口（节点字段编辑 + 增删 + 实时预览），不支持拖拽连线。
  • sub_workflow 子工作流节点未实现：YAML 里写了会显式报错，不会静默跳过。
  • 没有 CI / Dockerfile：以 run.bat + verify_env.py 替代，Windows 本地即可验证。

5. 这个包是怎么被验证过的

打包脚本 scripts/package_submission.py 每次都会：① 逐文件算 SHA256 写进包根 MANIFEST.txt； ② 解压到临时干净目录；③ 跑 verify_env.py --with-tests 与 verify_matrix.py； ④ 装演示数据后核对 trace 数 / 日志数 / 交付文件数；⑤ 检查 run.bat 纯 ASCII、run.ps1 带 BOM 并实跑 run.bat -DryRun。任何一项不过就不出包——所以你解压看到的，就是被验证过的那一份。

遇到解压异常时，可用 MANIFEST.txt 里的 SHA256 对比，判断是传输损坏还是包本身问题。

Aegis · 编排即数据：一条流水线怎么跑写在 YAML 里，模型写的代码能不能算“通过”由物理断言裁决，而不是模型自己说。
