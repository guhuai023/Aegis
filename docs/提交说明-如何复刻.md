## 1.5 两个版本，按你的条件选

| 版本 | 文件名 | 大小 | 需要 Python? | 需要联网? |
|---|---|---|---|---|
| 常规版 | `Aegis-提交包-<日期>.zip` | 13 MB | 需要（3.11~3.14） | 首次装依赖要联网（约 60 MB） |
| **离线版** | `Aegis-提交包-<日期>-离线版.zip` | 约 100 MB | **不需要** | **不需要** |

离线版里内置了 `runtime/python314/`（官方嵌入式 Python 3.14.6 + 锁定版本的依赖），
`run.bat` 会自动优先使用它：**不装 Python、不装依赖、不联网**，双击即启动。
依赖版本固定在 `scripts/offline/requirements-lock.txt`，与验证环境完全一致。

## 2. 三条复现路径，按你的时间选

### 路径 A · 只看成果（约 5 分钟，零安装）

不需要 Python，不需要联网：

1. 打开 `docs/方案书.pdf` —— 看整体方案、架构、六条工作流、已知限制、验证结论；
2. 打开 `docs/Aegis-赛道一-方案讲解.pptx` —— 14 页正文，讲稿在每页备注里；
3. 播放 `docs/Aegis-演示视频.mp4` —— 3 分 04 秒，画面全部取自真实运行记录（无动画伪造）。

**为什么信任视频**：视频里的每个数字（8 节点、10562 tokens、9 执行步、160 项测试）都能在路径 B/C 里自己复现出来。

---

### 路径 B · 不填 Key 也能验证（约 10 分钟，需要 Python）

这一条是本作品的重点：**没有大模型 Key，也能看到真实运行记录**。

1. 双击 `run.bat`
   - 首次会自动建 `.venv`、装依赖（`streamlit` / `openai` / `pyyaml`，需联网一次）、
     把 `seed/` 的 10 条真实 trace 装进运行库，然后起服务；
2. 浏览器打开 `http://127.0.0.1:8507`；
3. 左侧「最近任务」里逐条打开，或直接访问：

   | 地址 | 内容 |
   |---|---|
   | `/?trace=43d6b6a9` | data_pipeline 全绿：两条支线并行 + 汇合，8 节点完成、4 份交付物 |
   | `/?trace=c670d464` | 数据质量门禁：断言写的是业务不变量（行数/金额/地区/渠道） |
   | `/?trace=d8d78c4f` | 运维值班周报：日志分析 → 报告验收（report.md） |
   | `/?trace=f9e8ab41` | Excel 报表：明细/汇总/合计，可下载 .xlsx |
   | `/?trace=43cbcac1` | **熔断 → 人工一句话 → 预算重置 → 第三次通过**（完整人工干预） |
   | `/?trace=d70f9e90` | **真实失败**：模型没按规格输出、缺断言段，引擎拒绝执行（不是伪装成功） |

4. 再看「编排画布」页：切换工作流下拉，可以直接改字段（如 `max_retries`、`on_failure`）、
   保存到 `workflows/`，引擎热加载新策略；
5. 跑离线自检（可选但推荐）：

   ```powershell
   .venv\Scripts\python.exe scripts\verify\verify_env.py --with-tests
   ```

   预期输出：`160` 项测试 `OK`、演示库 10 条 trace、端口空闲、Key 未配置（黄色提示属正常）。

### 路径 C · 填 Key 真跑（约 30 分钟，需要 DeepSeek API Key）

1. 用记事本打开 `.env`（`run.bat` 首次会自动从 `.env.example` 生成），填入：

   ```
   DEEPSEEK_API_KEY=sk-你的key
   DEEPSEEK_BASE_URL=https://api.deepseek.com
   ```

2. 重启 `run.bat`，确认右上角显示「引擎运行中」；
3. 控制台左侧「任务下发」选 `code_gen`，需求描述用默认那句，点「启动任务」；
4. 看节点逐个完成、断言逐条通过；任务完成后「任务交付物」里能下载 `main.py` 等产物；
5. 想验证「同引擎换策略」，把下拉切到 `data_quality_gate`，点启动（需要 `openpyxl` 的
   `excel_report` 同理）。

**预期结果**（真跑结果非确定，但形态一致）：
- 节点状态从「运行中」→「完成」，工具节点显示断言通过；
- 端到端 2~4 分钟，消耗几万 tokens；
- 失败时会走修复回边，修复预算用尽转人工，控制台会提示人工介入。

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 双击 `run.bat` 闪退 | 没装 Python 或没加进 PATH。装 3.11+ 并勾选 “Add python.exe to PATH”，重开命令行验证 `python -V` |
| 双击后满屏乱码/`'xx' 不是内部或外部命令` | 旧版包的编码问题（已修）：cmd 用 GBK 读 `.bat`，文件里不能有中文。现在 `run.bat` 是纯 ASCII 外壳，中文与逻辑都在 `run.ps1`（UTF-8 带 BOM）。若你拿到的是旧包，请用 `docs/HOW-TO-RUN.txt` 里的手动步骤 |
| 系统里没有 PowerShell / 被策略禁用 | 按 `docs/HOW-TO-RUN.txt` 手动执行 5 条命令（不需要 PowerShell） |
| 想在装依赖前先看看环境对不对 | `run.bat -DryRun`：只报告（解释器/venv/依赖/.env/演示数据/将执行的命令），不安装、不改文件 |
| 走了一两步就中断，提示 `NativeCommandError` | 旧版启动脚本的问题（已修）：PowerShell 5.1 在 `$ErrorActionPreference='Stop'` 下会把原生命令写 stderr 当致命错误。现在改为显式判断退出码。若仍是旧包，用 `docs/HOW-TO-RUN.txt` 手动执行 |
| `pip install` 卡住/失败 | 换镜像：`.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 界面显示「引擎未启动 —— 已有引擎在运行」 | 上次的进程没退干净（引擎有单写者租约，防止旧 Agent 定义抢任务）。关掉旧窗口/进程后重开；确需并行启动可设 `AEGIS_ALLOW_MULTI_ENGINE=1`（不推荐） |
| 启动任务报 Key 相关错误 | 没配 `DEEPSEEK_API_KEY`。不填 Key 只影响“发起新任务”，看演示数据与离线测试不受影响 |
| `excel_report` 失败提示缺模块 | `pip install openpyxl` |
| 端口 8507 被占用 | 关掉占用进程，或改用 `--server.port 8508` 启动 |
| 画布是空的 | 工作流 YAML 被改动坏了。`python -c "from core.workflow import load_workflow; print(len(load_workflow('code_gen').nodes))"` 会给出明确报错 |

## 6. 我们没说能复现的部分（诚实清单）

- **真跑结果不是逐字节确定**：大模型输出有随机性，同一条工作流两次运行的文案与 token 数
  会有差异；可复现的是**流程形态与验收结论**（节点状态、断言结果、产物结构），不是每个字。
- **`sub_workflow`（子工作流节点）未实现**：YAML 里写了会**显式报错**，不会静默跳过。
- **没有向量检索（RAG）**：DeepSeek 未提供 embedding 接口，方案书里写清了“什么条件下会加”。
- **画布不是自由拖拽编辑器**：它是 YAML 的可视化入口（节点字段编辑 + 增删），不支持拖拽连线。
- **沙箱是进程级**（子进程 + 独立 venv + 工作区隔离），不是容器级隔离。
- **`scripts/demo/` 依赖 Microsoft Edge + CDP**：只用于重新生成演示视频，评委无需运行。
- **没有 CI / Dockerfile**：以 `run.bat` + `verify_env.py` 替代，Windows 本地即可验证。

## 7. 这个包是怎么被验证过的

打包脚本 `scripts/package_submission.py` 会做三件事：

1. 逐文件计算 SHA256，写入包内 `MANIFEST.txt`（可核对是否被改动）；
2. 解压到临时目录，在**干净路径**下跑 `verify_env.py --with-tests`；
3. 跑 `verify_matrix.py`，确认控制结构矩阵 14/14。

也就是说：你解压后看到的目录结构，就是被验证过的那一份，不是“另做一份干净的”。
